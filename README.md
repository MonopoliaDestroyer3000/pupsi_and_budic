# Budget-aware openJiuwen harness

Решение openJiuwen Challenge 2026: локальные инструменты решают распознанные задачи бесплатно, общий планировщик распределяет переменный бюджет между остальными. Харнесс запускается настоящим `openjiuwen.core.runner.Runner` как пользовательский `BaseAgent` с `AgentCard`.

## Сборка и запуск

```bash
docker build -t hack:latest .
docker run --rm --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python hack:latest \
  /app/run_agent.py --tasks-dir /data/tasks
```

Работает и обычный `docker run … hack:latest --tasks-dir /data/tasks`. В примере организаторов у `docker build` отсутствует контекст; здесь добавлена завершающая точка.

`LLM_BASE_URL` — полный базовый URL OpenAI-совместимого прокси, обычно `http://proxy:8000/v1`; к нему добавляется `/chat/completions`. `LLM_API_KEY` передаётся только в HTTP-заголовке. В образе ключей нет. Внешние API, локальные модели и скачивание данных при запуске не используются.

`BUDGET` читается при каждом запуске, **100000 — только значение по умолчанию**. Допустим любой конечный неотрицательный бюджет, включая ноль. `--budget` позволяет переопределить его для эксперимента. Если бюджет не передан организаторами, используется 100000.

После каждого решения атомарно сохраняется `answer.txt` в **корне каталога задачи**. Для соответствия формулировке примеров ответ также копируется в `workspace/answer.txt`, если workspace существует. Исходники кодовых задач исправляются в их workspace; тесты не редактируются. Если предоставлен `--output-file /data/tasks/solutions.json`, дополнительно после каждого ответа и события сохраняется общий JSON с результатами, бюджетом и диагностикой. Поддерживаются `--output` и переменная `OUT` (файл либо существующий каталог). Значимые логи идут в stderr, итоговый JSON — в stdout.

Дополнительные настройки:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `AGENT_CONCURRENCY`, `--concurrency` | 3 | Одновременно до 5 задач, общее ограничение токенов |
| `TIME_LIMIT`, `--time-limit` | 3450 с | Запас до внешнего часового таймаута |
| `AGENT_MODEL`, `--model` | qwen3.8-27b-noreason | Первый экономный проход |
| `REASONING_MODEL`, `--reasoning-model` | qwen3.8-27b | Повторная попытка и сложные шаги |
| `--resume` | выключен | Повторно использовать сохранённые ответы; кодовые решения перепроверяются |
| `--deterministic-only` | выключен | Не обращаться к LLM, независимо от наличия ключа |

Все четыре разрешённые модели поддерживаются, другие имена отклоняются. При отсутствии ключа или URL выполняются бесплатные решения, остальные задачи остаются без ответа. При HTTP 401/402/403/429 новые задачи не запускаются, чтобы не создавать поток заведомо бесполезных запросов.

## Устройство решения

1. Из `task.json` в рабочую структуру допускаются только `task_id`, `task_type`, `instruction`, `reward`. Поля `expected`, `check` и любые другие метки не попадают ни в решатель, ни в промпты, ни в признаки планировщика.
2. Бесплатный проход по всем задачам: строгий интерпретатор операций над складским запасом; CSV-агрегации с проверкой полного покрытия условий; поиск в markdown-базе со связями mentor/employer; консервативные AST-исправления стандартных Python-функций.
3. Кодовое исправление принимается только после выполнения полного неизменённого набора видимых unittest-тестов. Нулевое число тестов успехом не считается. Непрошедшее исправление откатывается побайтно. Видимые тесты не гарантируют прохождение скрытых, поэтому независимый синтетический оценщик дополнительно проверяет крайние случаи.
4. Для оставшихся задач вычисляется ожидаемая полезность `reward × P(success)`. Приблизительный рюкзак с максимум 2000 ячейками выбирает портфель по доступному бюджету; порядок внутри портфеля определяется отношением ожидаемой полезности к расходу. План пересчитывается после результатов попыток.
5. Начальная оценка расхода зависит от типа, размера файлов и длины инструкции. После оплаченных попыток расход и вероятность успеха обновляются сглаженными наблюдениями по семействам. Это простой онлайн-оценщик; обученных нейросетевых весов нет. Стартовые оценки для math/search/CSV/coding: 850/1400/1800/3700 эквивалентных выходных токенов. Это инженерные априорные значения, не статистика реального прокси.
6. Экономный JSON-цикл предоставляет `list`, `read`, `grep`, `python`, `write`, `test`, `answer`, `skip`. Контекст ограничивается исходной задачей и последними взаимодействиями, число шагов ограничено 7/10, повторение одинакового действия прерывается. Более дорогая повторная попытка получает пониженную вероятность успеха и конкурирует с ещё не решёнными задачами.

Распознанное отсутствие обязательного файла, сущности/поля базы знаний либо конфликт буквальных утверждений теста позволяет отказаться до обращения к LLM. Неподдержанная формулировка не приравнивается к невыполнимости и остаётся кандидатом на модельный проход. Эти правила эвристические: на иной структуре задач возможны ошибочные отказы.

## Учёт бюджета

Для каждого ответа прокси учитывается `prompt_tokens / 10 + completion_tokens`. Весь вход считается без скидки за кеш. Reasoning внутри `completion_tokens_details` не суммируется второй раз; отдельно вынесенный reasoning и `total_tokens` используются для восстановления полного расхода. При отдельном reasoning без total применяется консервативное сложение.

Перед запросом под общей блокировкой резервируется верхняя оценка входа (число UTF-8 байтов плюс накладные расходы) и разрешённый выход. Резерв учитывает параллельные запросы и локальный лимит задачи. После ответа он заменяется фактическим usage. Отсутствующий, частичный или испорченный usage и неудавшийся HTTP-запрос списываются по резерву, чтобы такая попытка не стала бесплатной во внутреннем планировщике. Поэтому внутренний расход иногда выше реального расхода прокси. Если сам провайдер возвращает usage выше лимита, он полностью записывается, дальнейшие запросы блокируются; жёсткий внешний лимит остаётся у прокси организаторов.

## Границы инструментов и среда

Пути чтения и записи разрешаются внутри workspace; метаданные, скрытые файлы и файлы тестов защищены от модельных правок. Вычислительный Python-инструмент не предоставляет shell, сеть, установку пакетов и произвольные импорты. Чтение ограничено workspace и библиотеками интерпретатора; файлы доступны только для чтения, включая `io.open`. На Linux ограничены память и размер вывода вычисления. При неудаче откатываются все модельные записи, включая новые файлы и CSV.

Unittest запускается отдельным процессом с очищенным окружением без ключей прокси, ограничением времени/вывода; на Linux завершается вся группа процессов. Тесты и код задач всё же исполняются Python-интерпретатором: окончательная изоляция обеспечивается контейнером организаторов. Встроенные ограничения инструментов не заменяют OS sandbox.

Образ закреплён на `python:3.12.10-slim-bookworm`, openJiuwen — `0.1.19`, все устанавливаемые пакеты закреплены в `requirements.txt`. Установка идёт с `--only-binary=:all: --no-deps`: включена проверенная цепочка импортов используемых `BaseAgent`/`Runner`, без неиспользуемых интеграций полного дистрибутива openJiuwen. Поэтому `pip check` может сообщать о необязательных для этого пути интеграциях. При сборке выполняется настоящий smoke-test агента. Не следует заменять установку обычным незакреплённым `pip install openjiuwen`: это подтянет лишние зависимости.

## Проверки и собранные траектории

```bash
python -m unittest discover -s tests -v
python tools/benchmark.py --tasks-dir task-dir --output results/sample_evaluation.json
python tools/benchmark.py --synthetic --count 100 --seed 20261113 --output results/synthetic_evaluation.json
```

Локальные тесты и обычный бенчмарк требуют только Python 3.12. Флаг `--with-framework` включает openJiuwen; для него установите закреплённые зависимости через `python -m pip install --only-binary=:all: --no-deps -r requirements.txt`. Флаг `--without-framework` у основного CLI предназначен исключительно для автономных тестов; официальный запуск его не использует.

Генератор тренировочного набора:

```bash
python tools/generate_training.py --output .work/training --count 1000 --seed 74 --impossible-fraction 0.2
```

Генератор хранит oracle отдельно от `task.json`; бенчмарк запускает агент на временной копии без oracle и полей оценки, сверяет неизменность тестов, проверяет ответы независимым оценщиком и добавляет скрытые синтетические coding-кейсы. Исходные примеры сохраняются неизменными. Набор является шаблонным и не оценивает обобщение на неизвестное распределение организаторов.

В `.github/workflows/verify.yml` подготовлены сборка и прогон с ограничениями контейнера; workflow ещё не запускался на GitHub. Ключа реального LLM-прокси и скрытого набора нет, их совместимость/результат не заявляются как проверенные.
